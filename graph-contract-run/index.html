防默写的记录

没有记录。--original-overlap 没有传，按默认的 auto 生效：作者写出的内容整体与原版重复不超过 40% 时什么都不说；超过之后，每次作者调用都会被告知限制和自己的数字，单个函数（比较行数 8 行以上）重复超过 60% 的文件被退回，一个文件最多退回 1 次。两个作业都没有走到作者会话，所以退回的文件数是 0。这个 0 表示机制没有被用到，不表示没有发现默写。

对测试设计阶段的发现

你打算先优化测试设计再重跑。下面是这次在真实项目上量到的、和这个阶段直接有关的问题，按影响大小排列。编号对应问题列表。

  1. 默认预算装不下测试设计（E-2）。设计步骤的截止时间用的是 check_validation.budget_seconds，默认按“每个检查 90 秒加每个节点 60 秒”算，这里是 17,670 秒，约 4 小时 54 分。设计者固定 4 个并行，作业 1 里 45 个节点用了 84 分钟，87 个节点的第 1 轮按这个速度要约 2 小时 40 分。每个测试顺序跑 3 遍，实测约 7.5 秒一遍，约 200 个文件验证一轮要 80 分钟以上，之后还有敲除。再加第 2 轮、评审，以及“有文件被退回就全体重跑”的最终验证，默认时间不够，作业 1 会在截止时以 0 个被接受的测试结束。
  2. 评审是一次 900 秒的调用（E-1）。所有被接受的测试交给一个评审会话，要求每个文件一个结论；评审失败或不完整，全部测试作废。87 个节点规模下是约 210 个文件、2 MB 测试源码、1.1 MB 的请求。离线试验里 13 个文件拆成 3 个会话用了 182 秒。
  3. 静态检查把 model.eval() 当成禁用的 eval（E-4）。规则取的是被调用的属性名，所以 model.eval() 命中了禁用列表里的 eval。第 1 轮 72 处调用、21 个文件因此被退回，其中 20 个文件没有别的问题；6 个节点的全部文件只因为这一条被退回。反馈给设计者的只有代码 forbidden_call，不说是哪个调用。
  4. 保留的旧检查当不了节点证据（E-continuation-2）。检查的包装脚本需要 git，导出目录没有 .git，所以 137 个检查没有一个算有效，87 个节点全部进入测试设计。这一条决定了设计阶段的工作量。
  5. 设计会话的 900 秒上限偏紧。86 个完成的会话里 5 个超过 750 秒；DensePose bootstrap 节点在作业 1 超时、在作业 2 用了 635 秒完成，ViT 节点在作业 2 超时（E-continuation-5、E-continuation-6）。
  6. 中途停下就要全部重来。冻结完成之前没有检查点，resume 用不了；每轮的退回原因只在内存里。作业 2 靠运行器把逐字节相同的请求直接用作业 1 的回答作答，省掉了 148 个会话，也就是作业 1 已经花掉的 7.1 个会话小时和 $200.38。优化后提示词会变，这些记录在重跑时用不上。
  7. Python API 和命令行的默认值相反（O-3）。ExecutionController(check_validation=None) 表示关闭检查验证，命令行不给 --check-validation 表示用默认策略开启。之前的 Detectron2 启动脚本走 Python API，实际是关着跑的。

偏离和放宽

你要求绕过问题时不关检查、不放宽验收，实在需要时要明确标出。下面几项需要标出。因为没有任何测试被接受、没有候选被验收，它们都没有影响到任何结果，但重跑时如果沿用就会生效。

  • 放宽 · GPU 交付检查的范围（O-6）。上一次运行的 GPU 对比把全部 66 个上游测试文件当验收标准。其中 18 个用了外部契约之外的名字，这次只把另外 48 个算作标准，18 个照跑但不计回归。不这样做就等于把转换剔除的检查放回来。
  • 放宽 · 评审的全有或全无（E-1）。nanolize 的规则是评审不完整就作废全部测试。我在设计者的运行器里把评审拆成多个并行会话，某个会话失败时只作废它自己的文件。每个被接受的文件仍然要有一个独立会话的结论。评审没有运行，这条规则没有实际用到。
  • 偏离“预算全部用默认值”（E-2）。作业 2 用的 nanolize 多一个本地提交：测试设计的截止时间从 budget_seconds 改成作业剩余时间的一半。数值参数一个没改，但这是代码层面的预算变化。提交在本地分支，没有推送到 claude/graph-contract。
  • 重放（E-2）。作业 2 里 148 个角色调用的回答来自作业 1 的记录，条件是请求逐字节相同。评审请求从不重放。
  • 清单的 goal 文字没有改。旧清单里写着“没有强制压缩比例，功能和全新安装通过后就停止纯体积优化”，转换后原样保留。这次没有影响，重跑时它会影响压缩力度。
