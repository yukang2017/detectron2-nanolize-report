G1　运行环境不够用：真实代码和 GPU 测试跑不起来 已做

问题
环境只按主持会话要映射的检查来装，项目自己的依赖、GPU 版的包和编译扩展都可能没有；原版上被跳过或因缺包失败的用例没有任何合计。
现在
skill 步骤 0 改了：环境装的是项目运行需要的依赖加测试工具。看到三种信号（模块导入不了、检查因缺包失败、用例因缺包或缺 GPU 版被跳过）时，主持会话不问人、先自己补救：缺包就补装，最多三轮；缺 GPU 版就换装；有编译扩展就写准备步骤；缺设备就给检查声明 gpus。一个环境的全部安装（创建加上之后的增量）合计最多 60 分钟，等 GPU 最多 10 分钟；补不了就带着最好的环境继续，并在总结里写明哪些模块导入不了、哪些测试没验证。代码两处：录完基线后发一条事件 unverified_on_original，合计原版上被跳过的用例和因模块导入不了而失败的检查；每条检查的结果里多了 case_skips（跳过的原因和个数）。提交前的试跑里每个功能有一个导入探针（见 N-T）。

现在
检查按声明的 GPU 张数分批发出，执行顺序不变：连续的、声明同样张数的检查是一批，一批申请的就是这个张数。所以一条要 12 张卡的检查不会连累旁边只要 1 张卡的检查，它自己记为没跑。要 GPU 的批次去 gpu_partition（配 gpu_qos），其余去 partition。只有一个分区时，所有批次都去那里，各自申请自己的检查声明的张数；不声明 GPU 的批次（包括探测批次）不申请 GPU。如果这个分区不收不带 GPU 的作业，在 check_executor 里写 "gpus": 1，每个批次就至少申请 1 张。GPU 批次在排队时限内没开始，或者调度器因为没有节点给得出这么多卡而拒绝它时，不再暂停作业：这些检查记为没跑（原因 no_gpu_within_wait_limit），发事件 batch_gpus_not_had，作业继续。调度器因为别的原因拒绝（账号、分区名、QOS、提交上限、时间上限、内存）仍然像以前一样停下作业，并带上调度器的原话。一次启动里，所有 GPU 批次白等的时间合计最多 10 个 queue_timeout；用完之后，每个 GPU 批次只等 1 分钟（queue_timeout 更短时按它）。有一个 GPU 批次跑起来，或者作业被恢复，就重新从头算。所有者的交付检查和原版测试的回放遇到同样的情况也不再停作业，交付带缺口。仍然会停的情况，停的说明里用检查的编号点出哪一条要了多少张卡。真实运行之后，check_executor 多了两个设置：gpu_request（GPU 申请用哪种写法：gpus、gpus-per-node 或 gres）和 gpu_minimum（一个要 GPU 的批次最少申请几张）。设了最少张数之后，声明的张数不超过它的检查合在一个批次里。站点用自己的规定当场拒绝某种写法时，作业把它当成拒绝立刻停下，说明里写着申请是怎么写的、该改哪个设置；不再当成“调度器没有回答”去重发。这两个值由主持会话在提交前问调度器问出来（只问，不提交）：先问默认的写法，被拒就换另外两种，再按 2、4、8 张问。入口多了两个选项 gpu_partition= 和 gpu_qos=，使用者给的队列照原样用；主持会话自己选队列时，如果问到的最早开始时间在一小时以后，它会把原先按名字排除掉的队列也问一遍，选一个能更早开始的，并在总结里写明。skill：检查声明“这条命令能跑起来的最少卡数”，不抄项目的官方配置；一个节点装不下的评测不作为这次运行的检查；调度器已经拒绝的申请不再原样提交。
怎么看到
设置 gpu_partition、gpu_qos 的含义变宽了（以前只管 GPU 上的性能测量）；新设置 gpu_request、gpu_minimum；入口选项 gpu_partition=、gpu_qos=；事件 batch_gpus_not_had，里面有 waited、allowance、next；检查结果里的原因 no_gpu_within_wait_limit；作业目录的 check-executor.json 里的 gpus_not_had。
例子

限制
单元测试用的都是假调度器；真的调度器上的情况见第 7 节的三次运行。跨节点的检查不做（方案里就不采纳）。GPU 分区的名字写错时，作业会停下并带上调度器的原话，不会记成“没跑”。评审 F 组对这个包提的 6 条重要问题都已修并合并。修了之后：没拿到 GPU 的检查把基线掏空时（所有保留的检查、或所有比较输出的检查都要 GPU），这次录制不保留，成对运行的主作业暂停、可以恢复；单个作业在冻结里，本机有 GPU 就把检查挪到本机，没有就以失败结束，并点出是哪条检查要了多少张卡。原版上没拿到 GPU 的检查，候选上不再发。敲除矩阵仍是一个批次，拿不到卡时去掉要卡最多的检查再发，最多三次。发到 gpu_partition 的批次申请的时间不超过那个分区的时间上限。因为设置把张数抬高了（gpu_minimum 或 gpus）而没有节点给得出时，作业会停下并点出是哪个设置，不会记成“没跑”（第八组评审的 H-2，已修）。设了 gpu_minimum 之后，GPU 上的性能测量会看到那个节点的所有设备。把作业的工作进程本身放到节点上跑的那种后端，仍然只会写原来那一种申请。一个运行中或暂停的作业不能改这两个设置，要重新提交。

N6　性能验收在带模型的 GPU 项目上给不出任何标准 已做
